# 环境与密钥配置说明

本文说明 **本地开发** 与 **生产环境** 如何配置敏感项（JWT、数据库、邮件等）。原则：**密钥不进 Git**，本地用 `.env` + `application-dev.yaml`，生产用环境变量 + `application-prod.yaml`。

---

## 1. 配置分层（怎么读这些文件）

| 层级 | 文件 | 是否提交 Git | 作用 |
|------|------|--------------|------|
| 公共默认 | `src/main/resources/application.yaml` | 是 | 全环境共用；`JWT_SECRET_KEY` **无默认值** |
| 本地 | `src/main/resources/application-dev.yaml` | **否**（.gitignore） | `spring.profiles.active=dev` 时加载；可有本地兜底密钥 |
| 本地模板 | `application-dev.yaml.example` | 是 | 复制为 `application-dev.yaml` 后修改 |
| 生产 | `src/main/resources/application-prod.yaml` | **否** | `spring.profiles.active=prod` 时加载 |
| 生产模板 | `application-prod.yaml.example` | 是 | 复制为 `application-prod.yaml` 后仅作结构参考 |
| 本地环境变量 | 项目根目录 `.env` | **否** | 由 `DotenvEnvironmentPostProcessor` 自动加载，**优先级高** |

启动时激活的 profile 由 `SPRING_PROFILES_ACTIVE` 决定（默认在 `application.yaml` 里为 `dev`）。

## 2. JWT 密钥（注册/登录报错时必配）

### 2.1 要求

- 算法：**HS256**
- 长度：**至少 32 字节**（建议 32+ 个 ASCII 随机字符）
- 用途：注册、登录、刷新令牌时签发 `accessToken`

未配置或过短时，接口返回：

```json
{
  "code": "SERVICE_UNAVAILABLE",
  "message": "app.jwt.secret-key 未配置或过短：HS256 至少需要 256 bit（32 字节），请设置环境变量 JWT_SECRET_KEY"
}
```

### 2.2 本地开发（推荐步骤）

1. 复制环境变量模板：
   ```bash
   copy .env.example .env
   ```
2. 生成随机密钥（PowerShell，任选其一）：
   ```powershell
   # 方式 A：.NET
   [Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))
   # 方式 B：Python
   python -c "import secrets; print(secrets.token_urlsafe(32))"
   ```
3. 在 `.env` 中设置（**不要用生产密钥**）：
   ```env
   SPRING_PROFILES_ACTIVE=dev
   JWT_SECRET_KEY=这里粘贴至少32字符的随机串
   ```
4. 确认存在 `application-dev.yaml`（可从 `application-dev.yaml.example` 复制）。
5. **重启** Spring Boot 应用（修改 `.env` 后必须重启）。

本地还可不配 `.env`：若 `application-dev.yaml` 中保留了开发占位默认值，也能启动；**仍建议用 `.env` 自己的随机串**，避免团队共用同一占位密钥。

### 2.3 生产环境

| 项 | 要求 |
|----|------|
| `SPRING_PROFILES_ACTIVE` | `prod` |
| `JWT_SECRET_KEY` | **必须由运维在服务器/容器/K8s Secret 注入**；≥32 字节；**与本地、与其他环境均不同** |
| 仓库 | **禁止**把生产密钥写入 `application-prod.yaml` 或 `.env` 并提交 |
| 轮换 | 更换密钥后，所有已签发 access/refresh 令牌失效，用户需重新登录 |

示例（Linux 进程环境）：

```bash
export SPRING_PROFILES_ACTIVE=prod
export JWT_SECRET_KEY='生产环境单独生成的长随机串至少32字符'
java -jar demo.jar
```

Docker Compose 示例：

```yaml
environment:
  SPRING_PROFILES_ACTIVE: prod
  JWT_SECRET_KEY: ${JWT_SECRET_KEY}  # 在宿主机 .env 或 Secret 中定义，勿提交仓库
```

`application-prod.yaml` 中应仅为：

```yaml
app:
  jwt:
    secret-key: ${JWT_SECRET_KEY}
```

**不要**在生产 yaml 里写 `${JWT_SECRET_KEY:某默认值}`。

### 2.4 本地 vs 生产对照

| 配置项 | 本地（dev） | 生产（prod） |
|--------|-------------|--------------|
| Profile | `dev` | `prod` |
| JWT 来源 | `.env` 的 `JWT_SECRET_KEY` 优先 | **仅**环境变量 `JWT_SECRET_KEY` |
| 默认值 | `application-dev.yaml` 可有本地占位 | **无**默认值 |
| 验证码 debug | 可 `APP_AUTH_VERIFICATION_DEBUG_RETURN_CODE=true` | 必须 `false` |
| 数据库 | 本机 `ai_gp` | 生产库账号/地址 |

## 3. 其他常用环境变量

| 变量 | 本地建议 | 生产 |
|------|----------|------|
| `MYSQL_HOST` / `PORT` / `DATABASE` | localhost / 3306 / ai_gp | 生产 RDS 地址 |
| `MYSQL_PASSWORD` | `.env` 或 `application-dev.yaml` | 仅环境变量 |
| `APP_AUTH_VERIFICATION_DEBUG_RETURN_CODE` | `true`（联调收验证码） | `false` |
| `MIMO_API_KEY` | `.env` | 密钥管理注入 |
| `ADMIN_PASSWORD` | 可选 | 强密码，环境变量 |
| `APP_COMPANION_MEMORY_ENABLED` | `true` | 每周六陪伴记忆总结 |
| `APP_COMPANION_MEMORY_SUMMARIZE_CRON` | `0 0 3 ? * SAT` | 总结执行时刻（cron） |
| `APP_COMPANION_MEMORY_DIGEST_TIME` | `08:00` | 用户本地周六推送回顾时刻 |
| `APP_COMPANION_MEMORY_MAX_MSG_PER_WEEK` | `200` | 单周纳入总结的消息条数上限 |
| `APP_COMPANION_MEMORY_MAX_CHARS` | `12000` | 长期记忆最大字符 |
| `AI_CHAT_VALIDATE_LLM_SETTINGS_ON_SAVE` | `true` | 保存 LLM 设置时探测 Key/URL/模型是否可用 |

完整列表见项目根目录 **`.env.example`**。

### 3.1 陪伴记忆（`app.companion-memory`）

| 配置键 | 环境变量 | 说明 |
|--------|----------|------|
| `enabled` | `APP_COMPANION_MEMORY_ENABLED` | 总开关；关闭后不总结、不注入、不推送 |
| `summarize-cron` | `APP_COMPANION_MEMORY_SUMMARIZE_CRON` | 每周六凌晨跑「先本周、后长期」两次 LLM |
| `digest-delivery-time` | `APP_COMPANION_MEMORY_DIGEST_TIME` | 与任务 08:00 提醒同窗推送 `pending_digest_text` |
| `digest-push-enabled` | `APP_COMPANION_MEMORY_DIGEST_PUSH` | 是否 WebSocket 推送回顾通知 |
| `max-messages-per-week` | `APP_COMPANION_MEMORY_MAX_MSG_PER_WEEK` | 控制总结成本 |
| `max-memory-chars` | `APP_COMPANION_MEMORY_MAX_CHARS` | 防止长期记忆无限变长 |

**配错表现**：未配置 `MIMO_API_KEY` 时周总结跳过该用户（日志告警），对话仍可用但不带长期记忆块。  
**数据库**：须执行 `scripts/mysql-existing-database-changes.sql`（或全量脚本中的 `user_companion_memory`）。

### 3.2 用户 LLM 设置连通性探测（`app.chat.validate-llm-settings-on-save`）

| 配置键 | 环境变量 | 说明 |
|--------|----------|------|
| `validate-llm-settings-on-save` | `AI_CHAT_VALIDATE_LLM_SETTINGS_ON_SAVE` | `PUT /users/me/llm/settings` 保存前是否调用模型接口探测 |

**配错表现**：返回 **400** `BAD_REQUEST`，`message` 说明 Key/URL/模型问题；配置**不会**落库。本地联调可临时设为 `false`。

### 3.3 头像与图片上传

| 配置键 | 环境变量 | 说明 |
|--------|----------|------|
| `upload-path` | `APP_UPLOAD_PATH` | 本地上传根目录，头像在 `avatars/{userId}/` |
| `public-base-url` | `APP_PUBLIC_BASE_URL` | 写入 `avatarUrl` 的主机前缀，默认 `http://localhost:8000` |
| `max-image-upload-bytes` | `APP_MAX_IMAGE_UPLOAD_BYTES` | 头像/对话附图单张上限，默认 5242880（5MB） |

接口说明见 **`md文档/HTTP接口-认证与用户.md`** 第 3.2.1、3.2.2 节；OpenAPI：`docs/openapi/v1-users.yaml`。

### 3.4 语音转写（`app.speech`）

| 配置键 | 环境变量 | 说明 |
|--------|----------|------|
| `enabled` | `APP_SPEECH_ENABLED` | 总开关 |
| `base-url` | `APP_SPEECH_BASE_URL` | 内网 STT 地址，默认 `http://127.0.0.1:9000` |
| `transcribe-path` | `APP_SPEECH_TRANSCRIBE_PATH` | 默认 `/asr` |
| `upstream-file-part-name` | `APP_SPEECH_UPSTREAM_FILE_PART` | 转发字段名，默认 `audio_file` |
| `max-audio-bytes` | `APP_SPEECH_MAX_BYTES` | 上传上限，默认 10MB |
| `read-timeout-ms` | `APP_SPEECH_READ_TIMEOUT_MS` | 转写超时，默认 120000 |

**部署 STT**：见 **`md文档/本地语音转写-STT部署.md`**。  
**配错表现**：STT 未启动 → **503** `SPEECH_UNAVAILABLE`；`enabled=false` → **503** `SPEECH_DISABLED`。

### 3.5 移动系统推送 uni-push 2.0（`app.mobile-push`）

| 配置键 | 环境变量 | 说明 |
|--------|----------|------|
| `enabled` | `APP_MOBILE_PUSH_ENABLED` | 是否调用系统推送 |
| `provider` | `APP_MOBILE_PUSH_PROVIDER` | 默认 **`unipush`**；仅非 uni-app 时用 `fcm` |
| `unipush-cloud-url` | `APP_UNIPUSH_CLOUD_URL` | uniCloud 云函数 **URL 化** 后的 HTTPS 地址（POST JSON） |
| `unipush-http-secret` | `APP_UNIPUSH_HTTP_SECRET` | 与云函数 URL 化「安全通讯」一致（可选） |
| `credentials-path` | `FCM_CREDENTIALS_PATH` | 仅 `provider=fcm`：Firebase 服务账号 JSON |
| `chat-reply-enabled` | `APP_MOBILE_PUSH_CHAT_REPLY` | 是否对 `CHAT_REPLY` 也发系统推送 |

**uni-push 2.0 推荐流程（运维）**：

1. [DCloud 开发者中心](https://dev.dcloud.net.cn/) → 应用 → **uni-push 2.0** → 开通并 **托管配置 Firebase**（及华为/小米等厂商）。  
2. 新建 **uniCloud** 云函数，依赖 **uni-cloud-push**，代码见仓库 `scripts/uni-push-cloud-function/index.js`。  
3. 上传部署 → **云函数 URL 化**（配置 path）→ 复制 HTTPS URL 到 `APP_UNIPUSH_CLOUD_URL`。  
4. 若启用 URL 安全校验，将密钥写入 `APP_UNIPUSH_HTTP_SECRET`（请求头 `unicloud-secret`，可按云函数内校验逻辑调整）。

**本地 `.env` 示例**：

```env
APP_MOBILE_PUSH_ENABLED=true
APP_MOBILE_PUSH_PROVIDER=unipush
APP_UNIPUSH_CLOUD_URL=https://xxxx.bspapp.com/http/uni-push-send
APP_UNIPUSH_HTTP_SECRET=
```

**前端（uni-app）**：manifest 勾选 uni-push 2.0、云打包；`uni.getPushClientId()` → `PUT /api/v1/users/me/push-tokens`；**无需**把 Firebase 服务账号交给本 Java 后端。

**数据库**：`scripts/mysql-existing-database-changes.sql` 中 `user_push_devices`。

**配错表现**：`enabled=true` 但未配 `unipush-cloud-url` → 日志告警，静默不发系统推送；站内通知 + WebSocket 仍正常。
